## 2. Working rules — every step, no exceptions

1. **Find the defect in a recorded response**, not by guessing.
2. **Census first:** count exactly which recorded questions the change can touch.
3. **Own switch, code default off, declared in compose,** and added to the startup switch registry
   (`switch_state.go`; its test fails if you forget).
4. **Pass criteria written before any image is built** (`reports/<step>/THRESHOLD_PREREGISTRATION.md`).
5. **Control arm first;** read the switch state from the running container before scoring.
6. **Measure:** the 103 corpus questions, the 14 everyday questions, the 38-check pre-flight, the 16
   relational probes, and any step-specific probe.
7. **Read the answers, not just the verdicts.** A check for one word does not check the sentence
   (U2b's "no ANPR sightings" was caught this way).
8. **Ship only if nothing correct is lost and nothing new is wrong.** Otherwise withdraw and record why.
9. **Record it:** `RESULT.md`, the capability log, compose comment, env file and state file (300 lines
   max), plus a tagged rollback image. **After every build, confirm the image timestamp changed** before
   deploying. On 2026-09-29 a ship build silently didn't run and the old code kept serving.
10. **Never:** fabricate, show PII the server didn't release, run destructive git or Docker commands,
    touch retained evidence, or run the test suite during a measurement.

**Ownership.** Claude: `api/**`, `semantic_layer/**`, measurement. Codex: `apps/**` (UI), guided by
`CODEX_UI_REDESIGN_PROMPT_20260929.md`. Product owner: decisions, git approval, hardware, investigator
questions. UI needs arrive in `docs/work/BACKEND_REQUESTS.md`.

### Phase B — REPRIORITISED 2026-09-29 by the product owner: runtime queries replace templates

**Owner direction:** every real question is answered by queries built at run time (the LLM and the
compiler, against the database), not by predefined templates. That puts roadmap G1 first.

Measured split of the 70 correct answers (`reports/templates-off-20260929/THRESHOLD_PREREGISTRATION.md`):
30 from an LLM-written plan, 25 from the run-time compiler, 11 from keyword templates (8 of them text
search over documents, transcripts and image text), and 4 terminal.

| Step | What |
|---|---|
| B0 | Templates-off census on the current build: every answer only a template gives, and every wrong answer the runtime path gives alone (`reports/templates-off-20260929/`) |
| B1r | Move the template-only answers onto the runtime path one family at a time, text search first (document, transcript, image text), each behind a switch and measured |
| B2r | Retire the templates family by family once templates-off ≥ templates-on with 0 new wrong |

**Gate:** templates-off at least as correct as templates-on, 0 new wrong, 38/38 pre-flight.

**Parked (built, switched off, not measured):** conversation router and glossary
(`FORENSIC_CONVERSATION_ROUTER`, `reports/conversation-router-20260929/`), and the evidence catalogue
counts and lists (was B2). Neither uses the database or the LLM, so neither serves the direction above.

### Phase E — the honest accuracy test and the model (needs the owner)

| Step | What |
|---|---|
| E1 | **About 50 investigator-written questions**, with verified answers and unanswerable ones included. Scored so a wrong answer costs more than a refusal. This becomes the headline number. |
| E2 | **GPU (24 GB) or a 32 GB+ machine.** Then compare SQL-trained models (Arctic-Text2SQL-R1 7B/14B, OmniSQL-7B) against the current 4B model on E1, under a decision rule written before the run. |
| E3 | Several candidate queries per question, answering only when their results agree. |
| E4 | An approved-question library: verified examples that guide the model (not templates). |

**Gate:** at least 80% correct on answerable investigator questions, 0 confident wrong answers, and 95%
of answers within 15 s.

### Phase F — new question types (2–3 weeks, after E)

| Step | What |
|---|---|
| F1 | Relationships computed, not just refused ("do any subscribers share a handset", via group and threshold) |
| F2 | Links across evidence types, only on links verified in the data. Powers the Connections page. |

| F4 | Entity profile ("everything about plate ABC-123"): counts per evidence type, first and last seen, top locations, linked media |
| F5 | Summaries and interpretation, once narration is fast enough on the GPU |
